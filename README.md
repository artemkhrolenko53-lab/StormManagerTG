# Storm Manager — этап 1: ядро бота

Тихая автомодерация Telegram-чатов (публичных и приватных, сколько угодно). Бот ничего не пишет в чат:
спам, скам, агрессия и флуд удаляются молча, всё видно только в панели администратора (Mini App, этап 2).

## Архитектура

```
Telegram ──webhook──▶ Vercel (FastAPI, api/index.py) ──▶ PostgreSQL (Neon / Supabase)
                           │                                   ▲
                           └─▶ Gemini (бесплатный ключ)        │
GitHub Pages (Mini App, этап 2) ──HTTPS API (initData)─────────┘
```

* **GitHub Pages** отдаёт только статику, то есть Mini App. Бот и API работают на Vercel (бесплатный план, лимиты проверьте при регистрации).
* Код не привязан к Vercel: `uvicorn api.index:app` запустит то же самое на любом VPS.
* Чат определяется по `chat_id`: все таблицы в базе привязаны к нему, правила и настройки у каждого чата свои.

## Каскад проверок (как сообщение проходит через бота)

1. Кэш сообщения (дубликаты доставки отбрасываются; правки `edited_message` проверяются заново).
2. Админы чата не модерируются (список кэшируется на 10 минут; если он неизвестен, сообщение пропускается).
3. **Уровень 1, бесплатные правила** (`storm/filters.py`): флуд, повторы, ссылки от новичков, спам-фразы, оскорбления, обход через похожие буквы и невидимые символы.
   * `clean`: ИИ не вызывается, квота не тратится.
   * `violation`: очевидное, действие сразу.
   * `suspicious`: неясное, идёт в ИИ.
4. **Уровень 2, ИИ** (`storm/ai.py`): сообщение передаётся как JSON-данные, правила чата подставляются в системный промпт, ответ приходит в структурированном виде (`response_schema`). Контекст: 3 прошлых сообщения без идентификаторов, число сообщений автора, «новичок» или нет. У каждого чата свой дневной лимит вызовов (`ai_daily_cap`, по умолчанию 200), чтобы не исчерпать общую бесплатную квоту.
5. **Решение** (`decide()`, чистая функция):
   * уверенность ИИ ≥ 90: удалить;
   * 60–89: в очередь администратору (Mini App), без удаления;
   * ИИ недоступен или упал: на подозрении ничего не удаляется, только очень сильные сигналы идут в очередь;
   * бан: только очевидный спам (≥ 95) от нового аккаунта. Больше никаких санкций (лестницы варнов нет).

Любая ошибка (например, у бота нет права удалять) записывается в журнал как `error`, чтобы админ увидел это во вкладке «Логи».

## Данные и приватность

* Кэш сообщений: `MESSAGE_CACHE_HOURS` (72 ч). Тексты в логах, очереди и жалобах стираются через `LOG_TEXT_RETENTION_DAYS` (30 дн.). Событие остаётся, текст нет. Очистка: `/cron/cleanup` раз в сутки (`vercel.json`).
* Жалобы анонимны: автор хранится только как хеш (для защиты от злоупотреблений), никто не видит, кто пожаловался.
* `audit_log` (действия админов) защищён триггерами: UPDATE, DELETE и TRUNCATE запрещены.
* Бесплатный уровень Gemini: Google может использовать отправленные сообщения для улучшения моделей. **Это нужно указать в «Кодексе» чата.** Для приватных чатов можно выключить ИИ (`ai_enabled=false`) или `AI_PROVIDER=none`.

## Запуск

1. **Токен.** Токен, который попал в переписку, считайте скомпрометированным: в @BotFather `/revoke`, возьмите новый. Никогда не коммитьте токены.
2. **База.** Создайте бесплатный проект Neon (или Supabase) и скопируйте *pooled* строку подключения в `DATABASE_URL`.
3. **Gemini.** Бесплатный ключ в Google AI Studio → `GEMINI_API_KEY`. Идентификатор бесплатной Flash/Flash-Lite модели в `GEMINI_MODEL` сверьте в AI Studio, названия меняются.
4. **Vercel.** Импортируйте репозиторий, добавьте переменные из `.env.example` (`WEBHOOK_SECRET` и `CRON_SECRET`: любые длинные случайные строки), задеплойте.
5. **Таблицы и вебхук** (с теми же переменными окружения локально):
   ```
   pip install -r requirements.txt
   python scripts/init_db.py
   python scripts/set_webhook.py https://<проект>.vercel.app
   ```
6. **В чате:** добавьте бота администратором с правами «удалять сообщения», «блокировать пользователей» и «приглашать пользователей». Без админ-прав бот не получит события `chat_member` и не сможет удалять.

## Тесты

```
pip install -r requirements-dev.txt
pytest
```
Интеграционные тесты сами поднимают встроенный PostgreSQL (`pgserver`): 43 теста, включая весь путь «сообщение → правила → ИИ → удаление/бан/очередь», правки, лимиты, ретенцию и неизменяемость аудит-лога.

## Что проверено и что нет

Проверено в песочнице: вся логика, SQL и схема на настоящем PostgreSQL 16, вебхук FastAPI (403 без секрета, 200 с ним), проверка `initData`.
**Не проверено:** деплой на Vercel, живые вызовы Telegram и Gemini (нет доступа к сети и ключей). Первый запуск смотрите по логам Vercel.

Ограничения этапа 1: модерируются текст и подписи (картинки и голосовые нет); бот знает участников только по их активности, поэтому «новичок» определяется по числу сообщений и, если бот видел вход, по времени входа.
